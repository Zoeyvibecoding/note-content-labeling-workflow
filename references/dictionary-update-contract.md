# 字典更新闭环

## 单一职责

- `components/meihu-labeling-engine/`：执行打标步骤、产品实例核验、反事实、近邻排除、结果验证和批量覆盖校验。
- 完整规则 JSON：每次任务运行时由引擎获取并锁定，是该批次的规则内容。
- HTML 字典：供人阅读、搜索和检查，是规则外显，不直接参与状态机执行。
- 父 Skill：负责数据筛选、Athena 内容获取、内容理解、引擎调用和 Excel 交付。

## 用户通知“字典更新”时

1. 运行 `components/meihu-labeling-engine/scripts/fetch-rules.mjs` 获取新规则。
2. 对比：
   - `rules_version`
   - `rules_hash`
   - 两大类、八小类及名称
   - `workflow.entry_step`
   - `workflow.steps`
   - 产品实例策略
   - 正向验证、反事实与近邻排除要求
   - 输出契约
3. 运行 `validate-rules.mjs`。
4. 若只更新规则内容且结构仍兼容：
   - 不复制旧规则；
   - 锁定新版本；
   - 对指定批次所有笔记重新执行完整状态机。
5. 若步骤、字段或输出结构变化：
   - 更新引擎脚本和测试；
   - 更新父 Skill 的字段映射、交付协议和校验器；
   - 运行全部测试；
   - 提交新版本后再打标。
6. 若线上规则无法获取、结构不完整或新旧消费者不一致，停止打标，不使用缓存兜底。

## 发布字典展示页

用户同时要求修改 HTML 时，修改原 Vercel 项目并发布到永久地址 `https://meihu-label-dictionary.vercel.app/`。发布成功后再核验 HTML 展示与规则 JSON 是同一版本。该动作不替代本仓库中的引擎兼容性检查。

若用户确认该展示版本要成为后续报告的内嵌字典基线，还必须同步更新 `assets/embedded-label-dictionary/` 的版本化快照与 `manifest.json`，把页面资源改为报告子目录可用的相对路径，更新报告协议和校验器并运行测试。只发布 Vercel 页面不构成报告内嵌基线更新。

## 版本影响

规则更新后，不只修正用户点名的几篇笔记。先识别受影响规则，再对本批次所有可能受影响记录重判；同一交付文件不得混用两个规则版本。
