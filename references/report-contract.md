# 复盘报告与 Vercel 发布协议

## 数据边界

- 只使用用户明确确认的 v2 过程文件。
- 报告中的笔记内容、标签、案例及后链路数据必须可回溯到 v2。
- 不从其他品牌报告、旧过程文件、网页搜索或模型常识补写事实。
- v2 更新后，废止由旧 v2 生成的待确认报告，重新生成新版本。

## 用户可读性

报告必须让未参与项目的人也能独立理解：

- 章节标题直接说明该部分回答的问题。
- 首次出现 CTR、CPUV、CPTI、Bench、IQR 时用一句话解释。
- 图表直接标注子类、指标、数值和方向，禁止只依赖颜色或悬浮提示。
- 结论同时给出数据依据和对应笔记案例，不只写判断。
- 内容公式使用具体内容结构与案例，避免行业通用空话。
- 内容公式按“认知起点 → 意义转化机制 → 产品结论 → 可信性闭环”提炼，再以“选题切口 + 使用场景 + 叙事过程 + 产品角色 + 效果证明”呈现；至少两篇同品牌、同子类、双指标或三指标高优笔记支持同一完整机制。共同成分、人设、场景或关键词不能单独构成公式。
- 样本标题必须与小红书原始标题完全一致，保留标点、符号和 emoji。过程文件无标题时依次读取原链接 `og:title`、页面标题，仍不可得时显示笔记 ID；禁止 AI 改写标题。
- 每个数据板块的结论紧跟小标题，只客观描述谁在哪个指标更好或更弱，并在括号中给出数据；不得代替客户判断内容“适合”何种目标。
- 子类明细按“大类·美垂及其四个子类 → 大类·破圈及其四个子类”排列，可折叠但默认展开。
- 子类明细结论必须依次覆盖大类差异、美垂四子类内部表现、破圈四子类内部表现，并附具体指标数字；不得只描述美垂或只描述破圈。
- 相邻章节只能保留一个分页符或视觉分隔符。交付前检查并清除连续重复分隔符，禁止同一章节边界同时叠加显式分页元素与 CSS 强制分页。
- Action List 写明动作、适用内容、执行方式和验收标准。
- 删除仅用于铺垫但不帮助理解的空泛说明。

## 计算口径

- `CTR = Σ点击量 ÷ Σ曝光量`，使用竞价运营口径。
- `CPTI = Σ竞价运营消耗 ÷ Σ新增TI`。
- `CPUV = Σ三方消耗 ÷ Σ站外UV`。
- 子类、大类和 Bench 均使用汇总分子除以汇总分母，不对单篇比率做算术平均。
- 0 值和经既定 IQR 规则判定的极端值不进入对应指标计算；在报告中说明排除口径。
- 所有本品、竞品和同池 Bench 必须使用相同计算逻辑。
- 高优笔记使用同品牌、同子类 Bench：本品与本品同子类比较，竞品与竞品同子类比较；不得用全池 Bench 混合判断。
- 本品子类明细数据以本品整体 Bench 着色：CTR 高于 Bench 为绿、低于为红；CPUV/CPTI 低于 Bench 为绿、高于为红；相等或无值为中性色。此处不得混用竞品或同池 Bench。

## 固定报告结构

### 内嵌打标字典（全报告强制）

- 每一份正式报告都必须内嵌父 Skill 的版本化字典快照，唯一基线由 `assets/embedded-label-dictionary/manifest.json` 指定；当前为 `v13-report-hierarchy-20260817`。
- 生成每个不可变报告版本时，先完成报告 HTML，再运行 `scripts/embed_dictionary.py <report_version_dir>`，把 manifest 的 `asset_path` 完整复制到该版本的 `dictionary/`，保持 `index.html`、CSS、脚本、规则 JSON 和字体的相对目录不变。
- 报告侧栏、顶部导航或其他首屏可发现的位置必须提供“打标字典”入口，指向或内嵌 `dictionary/index.html`；只放 `https://meihu-label-dictionary.vercel.app/` 外链不算内嵌。
- 内嵌字典必须保持当前信息层级：主标题为一级；“适用对象 / 最终输出 / 内容依据”合并为轻量补充说明带；“先判断内容属于哪一种打标类型”作为编号 `01` 的核心分类章节；不得恢复三个等高补充卡片或把补充说明与核心分类做成相同视觉层级。
- 禁止报告生成器重新拼写、删减或自行美化字典 HTML。若字典更新，先更新 Skill 资产快照与 manifest，再用于新报告；历史报告继续保留旧快照。
- 正式发布前运行 `scripts/validate_embedded_dictionary.py <report_version_dir>`。缺文件、文件漂移或报告没有 `dictionary/index.html` 入口均视为交付失败。
- 公网字典 `https://meihu-label-dictionary.vercel.app/` 仅用于人工核对最新版，不代替报告内嵌快照。

### 已确认母版继承（最高优先级）

- 用户已确认或明确指定的最新正常报告版本，是正式交付的页面母版与结构真值；新版本必须在该母版上更新，不得自行换版、删减章节或降低内容密度。
- 当前项目用户指定的基准母版为 `report-share-site/public/report-v21-trial.html`。后续版本必须保留其侧栏导航、KPI、结论卡、图表、完整指标表、高优池、内容公式、本竞品比较与 Action List 结构；用户另行确认新母版后才可替换。
- `components/content-diagnosis-reporting` 的简易 renderer 只用于数据链路校验和中间预览，不是正式报告母版，禁止直接发布为最终报告。
- `Miss` 必须局部化：某字段缺失，只影响依赖该字段的指标或判断；不得把单字段缺失自动扩大为整章或整份报告缺失。其余可计算数据、内容诊断和公式继续生成，并明确披露有效样本与缺失范围。

至少包含：

1. 报告概览：数据范围、核心指标和重点发现。
2. 本品内容大盘：大类结构、子类结构和子类效率。
3. 高优笔记与内容公式：由多篇有效样本归纳，并提供笔记案例。
4. 本品与竞品比较：结构差异、共有子类效率、竞品独占/共有/本品独占内容公式。
5. Action List：将发现转化为下一轮可执行动作和验收标准。

章节编号随实际内容连续排列，禁止保留空章节或错误编号。

## 版本记录

- 每次报告修改生成独立版本，不覆盖历史源文件。
- 在项目的版本目录保留版本号、生成时间、所用 v2 文件名和主要修改说明。
- 每个版本都使用独立、不可变的公开 URL；任何已发送给用户的 URL 不得改写内容、重定向到新版本或删除。
- 如需额外提供“最新版”别名链接，它只是附加入口；正式交付仍必须同时提供不可变的版本 URL。
- 报告确认记录保存 `analysis_id`、报告版本、不可变 URL 和确认时间。

## Vercel 项目与发布

- 每个新分析任务必须生成唯一 `analysis_id`，建议格式为 `{owner}-{spu_slug}-{YYYYMMDD-HHmmss}-{short_hash}`。
- 每个新 `analysis_id` 必须创建独立 Vercel 项目和新生产域名。禁止部署到其他 `analysis_id` 已使用的项目，即使分析对象或用户相同也不例外。
- 同一 `analysis_id` 的每个报告版本必须发布到唯一版本路径，例如 `/reports/v001/index.html`、`/reports/v002/index.html`；禁止在原路径上替换文件。
- 在当次任务的发布清单中持久记录 `analysis_id`、项目目录、Vercel 项目 ID、项目名、生产域名、版本、报告路径、完整 URL 和发布时间。
- 部署前必须对发布清单和远端项目执行冲突检查。若项目名、域名、报告路径或完整 URL 任一已存在，立即停止部署并生成新的唯一标识；不得询问后覆盖，也不得使用 `--force` 绕过。
- 不得删除、覆盖、重命名或重定向任何历史交付 URL 所对应的文件与部署。
- 不同用户必须使用各自授权的 Vercel 账号或工作区；未获得项目所有者明确授权时，不得发布到他人的 Vercel 项目。
- 若项目采用静态 `public/` 目录，将报告写入该项目约定的公开路径，并确保全部图片、字体和脚本使用可部署的相对路径或同项目静态资源。
- 先完成本地结构、数据和资源检查，再执行 Vercel 生产部署或触发已连接仓库的生产部署。
- 生产交付地址必须是本次部署实际返回或已绑定的 Vercel 公网 URL。
- `https://evidens-content-report.vercel.app/report.html` 仅作为“无需登录、任何人可访问”的参考示例，不作为固定项目或固定交付地址。

- 不得使用 `file://`、`localhost`、临时预览地址或 `chatgpt.site` 作为最终报告链接。
- 不得要求读者登录 ChatGPT、Vercel 或其他账号。

## 发布后硬门槛

发送链接前逐项验证：

1. 使用匿名、未登录浏览器直接打开生产 URL。
2. 页面返回正常报告，不跳转登录页、权限页或安全拦截页。
3. 再次读取发布清单，确认当前完整 URL 只对应当前 `analysis_id` 和当前版本，且所有历史交付 URL 仍能返回原版本内容。
4. 首屏标题、目录、数据概览可见。
5. 图表、报告截图、笔记链接和静态资源正常加载。
6. 目录锚点、外链和页面内导航可使用。
7. 控制台无阻断阅读的错误。
8. 检查报告概览、子类效率、内容公式、竞品比较和 Action List 的可读性。
9. 在桌面与窄屏各完成一次全页视觉验收，并与已确认母版逐项对照；确认不存在简易 renderer 标识、模板占位语、章节降级、异常空白、重复页面、溢出或不可读图表。
10. 打开报告内的“打标字典”入口，确认加载的是 manifest 锁定快照，补充说明与核心分类的层级清晰，九个标签完整，且不依赖 `chatgpt.site`。

任一项失败，不得发送生产链接或进入等待确认状态；修复、重新部署并重新验证。

## 最终确认

发送生产 URL、报告版本和本次主要修改后，进入 `REPORT_DELIVERED_WAITING_CONFIRMATION`。

只有用户明确确认报告，任务才完成。用户提出修改时保留现有版本，生成新版本、重新部署、重新验证并再次等待确认。
