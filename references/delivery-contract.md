# 最终交付协议

## 文件

交付一个 `.xlsx` 文件，文件名建议：

`{分析对象}_消耗Top{N}_笔记内容理解与打标过程文件_{规则版本}.xlsx`

包含且只包含两个用户工作 Sheet：

1. `视频笔记理解`
2. `图文笔记理解`

若某种媒介没有入选笔记，仍保留该 Sheet、表头和“本次无入选记录”的说明。

## 列结构

每个 Sheet 的顺序为：

1. 对象、排名、笔记链接与投放指标；
2. 对应媒介的全部内容理解过程字段；
3. 末尾三个标签字段：
   - `打标结果`
   - `打标结果原因`
   - `打标结果来源`

`打标结果来源` 应简洁包含：支持最终判断的核心内容证据、规则版本，以及必要时最关键的排除证据。不得只写“根据字典判断”。

## 顶部元数据

在每个 Sheet 顶部注明：

- 分析对象及本品/竞品角色；
- SPU name 与 nick name；
- 数据底表文件名；
- 数据时间口径：默认“底表全部时间范围”；
- 视频 Top N / 图文 Top N；
- 规则版本、规则哈希、规则获取时间；
- 内容来源声明：Excel 仅提供 ID、类型和投放数据；内容来自 Athena 与真实媒体理解。

## 公式与格式

- `CTR = 点击量 / 曝光量`
- `CPTI = 竞价运营消耗 / 新增TI人群`
- `CPUV = 竞价运营消耗 / 站外活跃UV`
- 分母为 0 或空时返回空白，不返回公式错误。
- 消耗保留合适小数位，数量使用整数格式，率使用百分比格式，ID 使用文本格式。
- 冻结元数据和表头，开启筛选；链接可点击。
- 长文本换行，列宽和行高可读，不把所有列压缩到一屏。
- 最终检查 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
- 分别渲染两个 Sheet 进行视觉复核。

## 内部审计

标签状态机轨迹、产品实例、反事实、近邻排除、规则快照和校验结果保存在运行目录 JSON 中。除非用户要求，不额外增加用户可见审计 Sheet，以维持最终文件简洁。
