# 两阶段交付协议

## 用户可见流程

向用户明确展示并严格执行：

**内容理解 → 发送 v1 → 等待确认 → 打标 → 发送 v2 → 等待确认 → 生成报告 → Vercel 发布 → 等待确认 → 最终完成**

三个“等待确认”均为强制暂停点。用户未明确确认时，不得自动推进。

## 第一次交付：v1 内容理解待确认

交付单位为 SPU：一个 SPU 交付一个工作簿，工作簿内同时包含视频与图文 Sheet。多个 SPU 必须输出多个工作簿，不得混在一个文件中。

文件名：

`{SPU}_视频Top{Nv}_图文Top{Ni}_v1_笔记理解过程文件.xlsx`

包含且只包含两个用户工作 Sheet：

1. `视频笔记理解`
2. `图文笔记理解`

若某种媒介没有入选笔记，仍保留该 Sheet、表头和“本次无入选记录”的说明。

每个 Sheet 包含且不得删减：

1. 对象、排名、笔记链接与全部投放指标；
2. `content-fields.md` 中对应媒介的全部内容理解过程字段；
3. 内容来源与追溯字段。

v1 不得包含 `打标结果`、`打标结果原因`、`打标结果来源`，也不得用隐藏列、备注或临时字段提前写入标签判断。

运行 `scripts/validate_delivery.py --phase content` 并完成双 Sheet 渲染检查后才能发送。发送后进入 `V1_DELIVERED_WAITING_CONFIRMATION` 并停止。

用户明确确认当前 v1 版本后，才允许冻结内容事实并进入打标。用户要求修改时保留旧文件，生成 `v1.1`、`v1.2` 等新版本并重新等待确认。

## 第二次交付：v2 内容理解与打标结果待确认

文件名：

`{SPU}_视频Top{Nv}_图文Top{Ni}_v2_内容打标过程文件_{规则版本}.xlsx`

直接复制用户确认的 v1 作为 v2 母版。对两个 Sheet 必须保持：

- Sheet 名称、行数和笔记 ID 集合不变；
- v1 所有列按原顺序位于 v2 左侧；
- v1 的列名、单元格值、公式、来源说明和格式不变；
- 不得用少量概括列替换 ASR、OCR、时间轴、图文结构、产品露出、关键原文、来源和复核说明等详细字段。

只在每个 Sheet 最右侧按以下顺序追加：

- `内容大类`
- `打标结果`
- `打标结果原因`
- `内容证据`
- `反事实检验`
- `最邻近标签`
- `排除原因`
- `置信度`
- `复核标记`
- `打标结果来源`
- `理解状态`
- `打标规则版本`

`打标结果来源` 应简洁包含支持最终判断的核心内容证据、规则版本，以及必要时最关键的排除证据。不得只写“根据字典判断”。

运行 `scripts/validate_delivery.py --phase labeled --v1-video ... --v1-image ...`、嵌入式结果校验和全批 reconciliation，并完成双 Sheet 渲染检查后才能发送。继承校验任一失败时禁止交付。发送后进入 `V2_DELIVERED_WAITING_CONFIRMATION` 并停止。

用户明确确认当前 v2 版本后，任务进入 `REPORT_GENERATION`，不得直接标记完成。用户要求修改时保留旧文件，生成 `v2.1`、`v2.2` 等新版本并重新等待确认。若修改涉及内容事实，必须退回 v1 阶段重新确认。

## 第三次交付：Vercel公开复盘报告

只使用用户确认的 v2 生成报告，并按 `report-contract.md` 保存版本、部署和验证。

生产地址由当次报告对应的 Vercel 项目生成并记录，不固定复用其他报告的域名或路径。

发送报告链接后进入 `REPORT_DELIVERED_WAITING_CONFIRMATION` 并停止。用户明确确认报告后，任务才进入 `COMPLETED`；用户要求修改时生成新版本、重新部署、重新验证并再次等待确认。

## 确认判定

可视为明确确认的表达示例：

- “内容理解确认，可以开始打标。”
- “v1 确认，继续打标。”
- “打标结果确认。”
- “v2 确认，可以生成报告。”
- “报告确认，可以完成。”

以下情况不得视为确认：

- 用户未回复；
- 用户仅下载或打开文件；
- 用户询问进度或文件位置；
- 用户只评价局部内容但未明确同意推进；
- 用户提出修改或仍在讨论口径。

## 顶部元数据

在每个 Sheet 顶部注明：

- 当前文件阶段与版本；
- 分析对象及本品/竞品角色；
- SPU name 与 nick name；
- 数据底表文件名；
- 数据时间口径：默认“底表全部时间范围”；
- 视频 Top N / 图文 Top N；
- 内容来源声明：Excel 仅提供 ID、类型和投放数据；内容来自 Athena 与真实媒体理解。

仅 v2 增加规则版本、规则哈希和规则获取时间。

## 公式与格式

- `CTR = 点击量 / 曝光量`
- `CPTI = 竞价运营消耗 / 新增TI人群`
- `CPUV = 三方消耗 / 站外活跃UV`
- 分母为 0 或空时返回空白，不返回公式错误。
- 消耗保留合适小数位，数量使用整数格式，率使用百分比格式，ID 使用文本格式。
- 冻结元数据和表头，开启筛选；链接可点击。
- 长文本换行，列宽和行高可读，不把所有列压缩到一屏。
- 检查 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
- 分别渲染两个 Sheet 进行视觉复核。

## 内部审计

标签状态机轨迹、产品实例、反事实、近邻排除、规则快照、用户确认记录、报告版本、部署地址和校验结果保存在运行目录 JSON 中。除非用户要求，不额外增加用户可见审计 Sheet。
